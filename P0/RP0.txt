\section{Introducción}

En este documento se presenta la ``Práctica 0'' del laboratorio de EDA II,
la cual introduce de manera preliminar algunas de las herramientas que
serán utilizadas a lo largo del curso, funcionando como un preludio de los
conceptos y procedimientos que se desarrollarán en sesiones posteriores.

Por ello, el objetivo principal de esta práctica es que el alumno
comprenda el uso adecuado de una LLM, conozca los fundamentos de
Git y GitHub, adquiera familiaridad con el entorno UNIX y comience a
``pensar'' en el lenguaje Java, comprendiendo de manera general cómo
se procesa y ejecuta un programa dentro de una computadora.


\section{Marco Teórico}


\subsection{Git [1]}

Git es un sistema de control de versiones distribuido que registra los
cambios de un proyecto mediante \textit{commits}, permitiendo conservar,
comparar y recuperar diferentes versiones de los archivos. Esto permite
tener una organización clara mediante un log de cómo fue cambiando
nuestro proyecto con cada actualización recibida, controlando a su vez
quien modifica y en que momento lo hizo
\cite{progit}.

Su funcionamiento básico puede describirse mediante cuatro etapas:

\begin{enumerate}[leftmargin=*, itemsep=2pt]

    \item \textbf{Working Directory:} contiene los archivos sobre los
    que se está trabajando y donde se realizan las modificaciones.

    \item \textbf{Staging Area (Index):} contiene los cambios que han
    sido seleccionados para formar parte del siguiente \textit{commit}.

    \item \textbf{Local Repository:} almacena permanentemente los
    cambios registrados mediante \textit{commits}, formando el historial
    del proyecto.

    \item \textbf{Remote Repository (GitHub):} almacena una copia del
    historial del proyecto en un servidor remoto, permitiendo sincronizar
    los cambios entre distintos entornos y colaborar con otros usuarios
    mediante comandos como \texttt{git push} y \texttt{git pull}.

\end{enumerate}

Las transiciones principales entre estas etapas son:

\begin{center}
\begin{tabular}{>{\ttfamily}l c >{\ttfamily}l}
\toprule
Estado inicial & Comando & Estado siguiente \\
\midrule
Working Directory & git add & Staging Area \\
Staging Area & git commit & Local Repository \\
Local Repository & git push & Remote Repository \\
\bottomrule
\end{tabular}
\end{center}

Por ejemplo, el flujo básico de trabajo es:

\subsection{Funcionamiento y ejecución de un programa Java [2]}

Un programa Java se escribe inicialmente como código fuente en un archivo
con extensión \texttt{.java}. Este código es transformado por el compilador
\texttt{javac} en \textit{bytecode}, almacenado en archivos con extensión
\texttt{.class}. El \textit{bytecode} no se ejecuta directamente sobre el
procesador, sino mediante una \textbf{Java Virtual Machine (JVM)}, lo que
permite ejecutar el mismo código sobre diferentes arquitecturas y sistemas
operativos \cite{jvms}.

Durante la ejecución, la JVM carga las clases necesarias y comienza a
ejecutar sus instrucciones. El código puede ser inicialmente interpretado,
mientras que las partes que se ejecutan con mayor frecuencia pueden ser
identificadas y compiladas dinámicamente mediante un compilador
\textbf{JIT (Just-In-Time)}. El JIT transforma dichas secciones de
\textit{bytecode} en instrucciones nativas optimizadas para el procesador,
mejorando el rendimiento durante la ejecución
\cite{jvms,java-vm-guide}.

El proceso general puede representarse mediante el siguiente flujo:

\textit{bytecode}, posteriormente cargado por la JVM y finalmente
interpretado o compilado dinámicamente mediante JIT para su ejecución
sobre el procesador.


\subsection{Comandos UNIX fundamentales [3]}

Los sistemas UNIX proporcionan una colección de comandos para
interactuar con el sistema de archivos, ejecutar operaciones sobre
archivos y directorios y consultar información del sistema. Entre los
comandos más utilizados se encuentran los siguientes:

\begin{enumerate}[leftmargin=*, itemsep=3pt]

    \item \textbf{\texttt{pwd}}:
    muestra la ruta absoluta del directorio de trabajo actual.

    \item \textbf{\texttt{ls}}:
    lista los archivos y directorios contenidos en la ubicación actual.

    \item \textbf{\texttt{cd}}:
    permite cambiar el directorio de trabajo.

    \item \textbf{\texttt{mkdir}}:
    crea uno o varios directorios.

    \item \textbf{\texttt{touch}}:
    crea un archivo vacío cuando no existe y, en caso contrario,
    actualiza sus marcas de tiempo.

    \item \textbf{\texttt{cp}}:
    copia archivos o directorios hacia otra ubicación.

    \item \textbf{\texttt{mv}}:
    mueve archivos o directorios y también permite cambiar sus nombres.

    \item \textbf{\texttt{rm}}:
    elimina archivos o directorios.

    \item \textbf{\texttt{cat}}:
    muestra el contenido de uno o varios archivos directamente en la
    terminal.

    \item \textbf{\texttt{grep}}:
    busca patrones de texto dentro de archivos o de la salida de otros
    comandos.

    \item \textbf{\texttt{chmod}}:
    modifica los permisos de acceso asociados a archivos y directorios.

    \item \textbf{\texttt{man}}:
    muestra el manual de un comando, proporcionando su sintaxis,
    opciones y descripción.

\end{enumerate}

Estos comandos constituyen una base práctica para la navegación,
gestión de archivos y administración elemental de un sistema UNIX.
Su combinación permite realizar desde operaciones sencillas, como
crear y mover archivos, hasta tareas más específicas, como buscar
información o modificar permisos.


\subsection{LLM}

Un \textit{Large Language Model} (LLM) es un modelo de inteligencia
artificial entrenado con grandes cantidades de datos textuales para
aprender patrones del lenguaje y generar, interpretar o transformar
texto. Su funcionamiento se basa principalmente en redes neuronales
profundas, generalmente de arquitectura \textit{Transformer}, que
procesan secuencias de texto y predicen los elementos más probables
según el contexto recibido.

Durante su entrenamiento, el modelo ajusta sus parámetros para aprender
representaciones y relaciones estadísticas presentes en los datos.
Posteriormente, estos parámetros permiten realizar tareas como
generación de texto, respuesta a preguntas, traducción, resumen y
asistencia en programación.

\section{Desarrollo}

\subsection{Funcionamiento práctico de ``Hola mundo''}

En esta parte de la práctica se creó el archivo \texttt{Hola.java} como
archivo fuente del programa. Para ello, se accedió a la terminal y se
ubicó la sesión de trabajo en el directorio correspondiente. Desde la
misma terminal se generó un archivo vacío con el nombre
\texttt{Hola.java}, sin incorporar inicialmente contenido alguno.

Posteriormente, el archivo fue abierto mediante Visual Studio Code, donde
se escribió el programa correspondiente al ejercicio de ``Hola mundo''.
Una vez finalizada la escritura y verificado el contenido del archivo,
se regresó a la terminal para realizar completamente desde ella el
proceso de compilación y ejecución, utilizando las herramientas
disponibles para Java en el entorno UNIX.

resultado esperado.

\subsection{Entrenamiento de LLM}

Como parte de la práctica se elaboró un \textit{prompt} destinado a
proporcionar a un modelo de lenguaje grande (\textit{Large Language
Model}, LLM) el contexto necesario para orientar sus respuestas de
acuerdo con las características del usuario y de la actividad.

Para ello, se especificaron elementos como la edad, el nivel escolar, el
curso en el que se encuentra el estudiante, el temario correspondiente y
el tema que se estaba estudiando en ese momento. El objetivo fue
establecer previamente el nivel de conocimientos esperado, el contenido
relevante y el tipo de respuesta requerido.

De esta manera, el \textit{prompt} funciona como una referencia
contextual para que la LLM pueda generar respuestas más adecuadas al
nivel académico del estudiante y mantener una orientación coherente con
los contenidos que se están trabajando. La intención no fue únicamente
obtener una respuesta puntual, sino proporcionar información suficiente
para mejorar la calidad del acompañamiento y la guía proporcionada por
el modelo.

\section{Conclusiones}

Con el trabajo realizado, es correcto concluir que se cumplieron los
objetivos planteados para la práctica. En primer lugar, se logró una
comprensión general del funcionamiento interno de Java mediante los
diagramas elaborados para representar su proceso de compilación y
ejecución. Asimismo, se realizó el entrenamiento de la LLM por parte de
cada uno de los integrantes restantes, estableciendo el contexto
necesario para orientar sus respuestas de acuerdo con las necesidades
académicas de cada participante.

De igual manera, se adquirió un manejo inicial de comandos UNIX durante
la creación, compilación y ejecución del archivo \texttt{.java}. Por
último, se obtuvo un mayor entendimiento de GitHub mediante la
investigación de su funcionamiento y la creación de un repositorio
propio para el trabajo colaborativo del equipo.

No obstante, debe hacerse énfasis en que el cumplimiento de estos
objetivos es todavía parcial. La comprensión y el dominio de estas
herramientas requieren continuar trabajando con ellas de manera
constante a lo largo del curso. Por ello, ninguno de los integrantes
puede considerarse, al menos por el momento, un experto en los temas
abordados, sino que esta práctica representa un punto de partida para su
desarrollo posterior.
